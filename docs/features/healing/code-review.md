## Checked and fine

- **Stored data.** One `spots` operation of objects, schema 2. It is left out when empty, so an untouched stack and its render hash are unchanged (`noSpotsChangesNothing`). The read is strict: unknown keys, modes and types, a missing position or id, or more than 100 spots make the whole stack unreadable through `EditStack.decode`, so editing turns off and nothing is written over. A newer `kindVersion` is kept in `preserved`, unread. Numbers must be finite and are clamped. No migration, no `PreviewCacheKey.currentPipelineVersion` bump, no existing golden touched. The three new goldens are new cases, not updates, and no tolerance was loosened.
- **Groups.** `Group.spots` exists only for the check box, and `presetGroups` leaves it out. Spots never move between photos through `copying` / `replacing` (whatever groups are passed), `AdjustmentPreset.init`, `decodeGroups`, `PresetFile` or `pasted(onto:)`, which keeps the target's spots and their on/off state. Presets saved as "all" (nil groups) still read as every preset group. `effective` drops spots that are off, and `offRendersAsNone` shows this byte for byte. Reset All (loupe and batch) clears spots.
- **Render order and frame.** `upstream` runs lens steps, then spots, then crop. Spots force `fullFrame` exactly as masks do, and `maskSourceSize`/`maskCrop` already handle frames that are not the full frame, so the overlay and clicks map correctly whether or not the decode is full frame (Spots off on a camera-cropped raw included). The 100% region renders the whole decode and crops afterwards, so spot positions use the mask frame's extent. `LiveRenderSession`'s `upstreamKey` hashes the spots, so a spot change rebuilds the stage. Previews, export and `photocli render` take the same `AdjustmentRenderer` path.
- **Kernels.** The ROI callbacks cover every sample (the bilinear neighbours and the 3 × 3 window inside `ring + 3`, and the source offset). The kernel is applied one pixel wider than it is kept, so the crop is real. Clamped input handles sources at the edge. `max(radius - inner, 1)` and the `1e-4` weight floor rule out division by zero. Kernel compilation failure gives the unchanged image (the Lens rule, a known limitation).
- **Automatic source.** Fixed candidate order and pure arithmetic, so it is deterministic. Candidates must lie inside the frame (1 px margin) and clear of the spot and every other spot, and the crop is preferred through a convex test. The luminance window is bounded (384 × 384). It runs on the `LiveRenderSession` actor, off the main actor. Placement and Choose Source Automatically ask the same question with the spots forced on, so the frame is always full (`sessionSourceMatchesPlacement`).
- **Tests.** Each acceptance criterion the PRD marks testable has a test that fails without the change: AC2, AC4, AC5, AC8, AC9, AC10, AC12, AC13, AC14, AC15. The CPU reference is plain Swift. It shares `SpotRenderer.Placement` with the renderer, but the AC2 test checks the heals at the scene's known speck positions on its own. All Swift Testing, no sleeps in PhotoCoreTests.
- **Concurrency.** The overlay and editor are main-actor. Accessibility actions use `MainActor.assumeIsolated` (AppKit calls them on the main thread). Source finding goes through the session actor, and nothing decodes on the main actor.
- **Project rules.** Menus read `LibraryMenuState` through `@FocusedValue`. The inspector uses `AppKitButton`, `AppKitSegmented` and `AdjustSlider`, with no SwiftUI `ScrollView`. The new strings are in the catalog (`LocalizationTests` passes). Preference keys are generic (`spots.mode` and so on), with no brand values. No new dependency, and `Package.swift` is unchanged. Nothing touches originals or sidecars, and edits are per file (`spotsArePerFileAndNeverSidecars`). Duplicate copies the stack (`duplicateCopiesSpots`). The debug-script verb `spot` is in `changing` and waits for placement and source inside its group. The algorithm comes from the cited papers only.
- **Keys.** H, V and ⌫ are handled only when the spot rules allow and fall through otherwise. Remove from Album is dimmed while a spot is selected. Esc deselects, then turns the tool off.
- **Security.** No `/security-review` is needed. The diff adds no subprocess, no network, and no file writes outside the library (`photobench scenes` writes test scenes to the folder it is given). The one new reader parses already-decoded stack JSON, strictly and with bounds. It is reachable from outside preset files too, but `AdjustmentPreset` discards the spots it reads there.
